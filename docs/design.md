# 3D 空间与交互设计

## 一、为什么是房间，不是星图

力导向星图适合看拓扑，不适合"知识库"的空间感。房间式固定结构，用位置记忆辅助回忆——数学在左翼、AI 在正中、化学在东南，每次进来位置一致。

规则：**3D 只做导航，不做阅读**。点节点弹 2D 详情层，正文始终在平面里读。

## 二、空间结构

```
                    中央大厅
                   （全局星图）
                        │
        ┌───────┬───────┼───────┬───────┐
        │       │       │       │       │
      数学      AI     化学    计算机   通识
      (左翼)  (正厅)  (东南)  (西侧)  (北侧)
                                    │
                                  工具间
                                 (东北角)
```

- **中央大厅**：各学科入口 + 全局依赖星图（节点量级见第六节，展台改按书计后需重算）
- **走廊**：连接大厅与各房间，走廊地面铺该学科的站名
- **房间**：一间一学科，房间内**按书分展台**，展台上立章节节点
- **工具间**：`tools` 类站点，独立小房间，不作为主路径

2026-11-25 定稿实测〔X〕：50 个仓库里有 131 份 `manifest.json`（25 站无 manifest，14 站是多书合集，最多一站 39 本），
抽取器落进 `data/` 的是 **129 条书目 / 去重 96 本独书**——131 份里有 2 份是 `_archive/` 旧版（排除并记 `excludedManifests`）。
所以展台数量级是「**129 条、最多 49 条一房**」，**同一仓库的多本书的展台要排在同一处并按书名分列**，
靠 `repo` 归组、靠 `bookSlug` 区分，不能合并成一个展台——合并就没法解释为什么一个展台上挂着两套 `ch01`。

## 三、节点层级

三层，逐层展开（量级取 2026-11-25 `data/manifest.json` 定稿实测〔X〕）：

1. **书**（展台，129 条 / 去重 96 本）：房间里的展台牌匾，牌匾上标仓库名 + 书名，唯一键 `repo + bookSlug`
2. **章节**（1,169 根）：展台上的立柱，高度按章节序号递增
3. **概念**（765 个）：立柱上的发光点，前置关系拉成细线

平均 **12.2 章/独书**（1,169 ÷ 96），按条目算是 9.1 章/条（1,169 ÷ 129，中位 7）；单本最多 39 章
（`algorithm-enlighten::clrs-companion`），最少 1 章（`chem-zhishu::equation-diagnosis`）。
之前按站点估的「约 650 章 / 415 概念」已失效〔X〕。

章节与概念两层不变，只是它们挂在「书」而不是「仓库」下面。跨书引用与前端索引一律用三段键
`{repo}::{bookSlug}::{id}`——`ch01` 这类 id 在同一仓库的多本书之间必然重复〔K〕。
**立柱光点的挂载只能反查 `concepts[].chapterIds`**（765/765 可解析），不能用 `chapters[].conceptIds`
（非空仅 15/1,169）〔X〕，实现见 `src/layout.ts::conceptsByChapter()`，原因见 `pitfalls.md` 已验证 17。
概念数 415 是说明文件汇总值，未过抽取器校验；probe 里 sudoku 的 manifest **没有 `concepts` 数组**〔M〕，
这类展台上只有立柱没有光点，属真实形态，不做假点填充。`contentLevel: stats-only` 的书仍是节点，
只是点开后不渲染正文、只给原站入口。

题目、卡片、术语不独立成节点，收进章节详情里。否则要再加 **3,541 题 + 4,100 卡 + 4,100 术语 = 11,741 个节点**〔X〕，
1,934 个真节点会涨到上万，3D 里全部糊成一团。

## 四、连接的语义

只有一种线：`prerequisites` 前置关系。

- 同房间内的连线：本学科颜色，半透明
- 跨房间的连线：只在中央大厅的全局星图上显示，房间内隐藏
- 无 `prerequisites` 的节点：孤立点，不画线，不做假线
- 但「旧版产物普遍没有前置链」这个前提要修正：probe 三站实测普遍有——章节 19/20、13/14、15/16，概念 49/50、58/61〔M〕。
  全库铺开后再修正一次〔X〕：**概念 428/765、章节 372/1,169 带 `prerequisites`**——约六成概念、三成章节有链，
  孤立点是常态但不是全部，画图上既不能按「整片孤立」设计，也不能假设每节点都出线。

## 五、交互

| 操作 | 行为 |
|---|---|
| WASD / 方向键 | 平移 |
| 鼠标拖拽 | 转视角 |
| 滚轮 | 远近 |
| 点击站点牌匾 | 侧栏展开该站信息卡（章数、进度、`contentLevel` 标记、入口） |
| 点击章节立柱 | 弹详情层，渲染正文 |
| 点击概念光点 | 弹概念层，含前置链与深度推导（若有） |
| 右上小地图 | 2D 俯视，显示当前位置、视野扇形、已访问区域 |
| 顶部搜索框 | 转检索层，不离开 3D（`/` 与 `Ctrl+K` 都能唤起，见第十一节） |
| `F` / HUD「走进」按钮 | 在轨道视角与第一人称漫游之间切换（见第十五节）；输入框聚焦时不劫持按键 |

详情层是 2D 面板，占屏幕 70%，可关闭。渲染路径按数据的 `bodyType` 与 `contentLevel` 分流，不是一条通道走到底：

| 情况 | 渲染 | 必须显示的提示 |
|---|---|---|
| `bodyType: "md"`（`contentLevel: full`） | markdown-it + KaTeX + Mermaid，公式走 `$...$` / `$$...$$`；Mermaid 围栏先出占位容器，可见才渲染（第十节） | 无 |
| `bodyType: "html"`（`contentLevel: degraded`，如 sudoku） | 正文是成品 HTML 片段，直接注入，**不过 markdown-it**；站内公式已是烤好的 KaTeX 节点，原始定界符取不回来〔N〕 | 顶部降级条：「正文为成品 HTML，公式不可还原」 |
| `contentLevel: stats-only` | 不渲染正文 | 只显示原站 Pages 入口，不留空面板 |

- 详情层底部给回溯条：`origin.path`（仓库内路径，用于对账）与 `bookSource`（原书出处，`page` 可能是区间字符串、整数或缺失〔M〕），三者按有无显示。
- 概念详情的「深度推导」区块按 `depth` 有无显示：全库 129 本实测非空 **82/765**〔X〕（三站口径 10/50、5/61〔M〕），
  不到两成，不能默认每页都有。
- 题目的 `answer` 是 int 索引〔M〕，前端按 `options` 原序渲染并现算字母，**不得重排选项**；`misconception`/`claims`
  实测全库恒空（`claims` 非空 **0/765**〔X〕），误解与断言区块无数据时整块不出现。
- AI 现场生成的内容属另一条通道，标「AI 现场生成 · 未经校验」，不与库内正文混排。

## 六、性能

| 手段 | 做法 |
|---|---|
| 合批 | 节点用 `InstancedMesh`，一个材质一批 |
| LOD | 距离 > 30 单位时，概念点隐藏，只留章节立柱 |
| 分片 | 进房间才加载该学科分片，大厅只加载 manifest |
| 纹理 | 文字用 CanvasTexture 生成，缓存复用 |
| 帧控 | 静止 3 秒后停渲染循环，交互时恢复 |

目标：桌面端 60fps；大厅全部节点不超过 15 万三角面。

节点量级按 `data/manifest.json` 定稿实测重算〔X〕，**一屏只渲染一个视图**（大厅 6 个分区灯塔，或一个房间），
所以预算按「最坏单房间」摊，不是按全库摊：

| 分区 | 书 | 章 | 概念 | 占 15 万预算 |
|---|---|---|---|---|
| ai | 49 | 450 | 320 | 最坏房间 |
| math | 45 | 265 | 308 | |
| general | 13 | 181 | 50 | |
| cs | 12 | 170 | 65 | |
| chem | 10 | 103 | 22 | |
| tools | 0 | 0 | 0 | 6 仓全无 manifest，空房间 |
| 大厅 | 6 个分区灯塔 + 6 条走廊 | — | — | 与房间无关的常数 |

- **单展台预算** = 150,000 ÷ 49（ai 房最多书数）≈ **3,060 三角面**。
- **章节环预算** = 3,060 ÷ 12.2 章/书 ≈ **250 面/章**；这是按独书均值算的，
  不是原「650 ÷ 96 ≈ 6.8 章/书」——旧口径会让每章的几何预算虚高一倍，落到 39 章的
  `clrs-companion` 上就爆。按最坏单本 39 章反推，同一展台只剩 **78 面/章**。
  两个数一起定尺度：**环上每章用低段数几何**（八面体 8 面、方柱 12 面一档），
  不用 UV 细分的球与圆环，把余量留给牌匾与前置线。
- 实测骨架（`InstancedMesh` 合批后）真数由 `__zhishu.triangles()` 读 `renderer.info.render.triangles`〔X〕：
  大厅 **1,398 面**、数学区（45 本 / 265 立柱 / 398 光点）**3,874 面**，占 15 万预算 **≤2.6%**——
  比原估的「约 2.8 万面」低一个数量级，因为六棱柱与方柱都是单段几何 + 合批，一次 draw call 提交全部实例。
  预算余量留给批 6 的牌匾纹理与前置线，不必再压段数。
  注意 headless 采样没有 vsync 上限，`fps()` 会报 165 而非 60，帧率达标以「单帧 ≈6ms」为准看，不是那个 165。
- 展台排布：同仓库的多本书排在相邻格位（`layoutRoom` 先按 `repo` 再按 `bookSlug` 排序），
  **不合并基座**——合并就没法解释同一展台上两套 `ch01`，且 129 本摊到六区后单区最多 49 本，方格阵一屏放得下。
- 文字仍是 CanvasTexture（含新增的走廊地面学科名，每区一张、6 张共 12 面），贴图缓存复用、不逐帧重建。

## 七、移动端 3D 适配（批 9）

批 9 删掉了 2D 降级视图（`src/svg2d.ts` 398 行、`MatrixFlat`、`?flat=1`、`#svg-root`、SVG 专用 CSS），
全端只有一条 3D 路径。「手机点开不能白屏」这条硬要求不变，实现从「换视图」改成**降画质 + 改构图 + 改手势**三段，
每段各有一条门槛判据。

### 7.1 画质档：开关集中在一个函数

`src/config.ts` 的 `qualityTier()` 是唯一开关源，`scene3d` 与 `spacekit` 只读结果，不散落在各 build 函数里。

| 开关 | desktop | mobile（`innerWidth < 768`） |
|---|---|---|
| dpr 上限 | 2 | 1.5 |
| 阴影 | PCFShadowMap 2048 | 关 |
| 光尘实例 | 不限（实测 398） | 220 |
| bloom | 开，0.65× 帧缓冲 | 关 |
| 房间帧缓冲 | 0.85 | 0.72 |

窄屏关 bloom 与阴影的理由写在 config 注释里：加法混合的大 quad 吃 fillrate，bloom 是多级降采样，
而阴影在 bloom 关掉之后仍要一整张 shadow map 的重绘。实测 390×844（deviceScaleFactor 2）
大厅 165.2 fps、数学区 146.2 fps，门槛线 30；桌面大厅 77.5 fps，门槛线 45。

### 7.2 构图自适应

`PerspectiveCamera.fov` 是**垂直**张角，水平张角 = $2\arctan(\tan(\mathrm{fov}/2)\cdot\text{aspect})$。
390×844 的 aspect 只有 0.46，沿桌面那套 fov 时水平视野被压到十几度，而八角厅六门横向铺到 ±157.5°，
默认机位进来只装得下正对的一面，走廊与邻区体量全出画；阅览室也一样，装不下三面墙就看不出「房间」。
所以 fov 与初始距离都按 aspect 走 `aspectRamp`（aspect ≥1 取 0 = 批 8 基线，≤0.55 取 1 = 竖屏）线性插值：

| 视图 | fov | 机位 |
|---|---|---|
| 大厅 | 56 → 76 | `hallPose()` 按水平视野解距离，竖屏 20 个结构点全入画 |
| 阅览室 | 56 → 76 | 横屏 `side*0.3`（站进门口，批 8 那一档）；竖屏 `side*0.5 − 1.5`（站门口看进去） |

阅览室竖屏**不求整间房顶点入画**：窄屏水平半角只有 20° 出头，要把两侧墙装下就得退到门外十几单位，
那是一张娃娃屋剖面图——书脊被压到 20px 以下，指头落进书顶的铜牌带，开出来是「本书总览」而不是章节。
判据因此分组（`frameCheck().groups`）：`face`（后墙书墙中段）/ `ceiling`（天花梁下远段）/ `floor`（地面中近段）
三段各 4/4 证明画面里有一间房，`back`（后墙四角）与 `sidewall` 只作参考量、不进判据；
「点得中」另由书脊投影像素高卡一条门槛（`spineProbe().px`，实测 math 39–51、ai 23–33，线取 ≥36）。

### 7.3 手势

OrbitControls 单指旋转、双指缩放；拾取沿用批 8 的 `faceIndex → (book, chapter)` 反查表，
不在触摸序列里再补一次射线。轻点判定在 `tapVerdict()`：触屏位移容忍 8px（**≥8px 一律判拖拽，不开书**），
鼠标 6px。门槛用 CDP `Input.dispatchTouchEvent` 打真实 touchStart → 两次 touchMove → touchEnd 验这条，
判据读 `lastTap().action === 'drag'` 且 `readerState()` 与滑动前逐字段一致。

### 7.4 光照与题签可读性（C1 / C2 / C3）

窄屏帧缓冲降档之后，批 8 那套灯光的两个老毛病被放大：天花与后墙近黑、书脊字口发虚。三段各有一条判据。

- **顶面打不亮不是灯不够，是法线朝下**。藻井、檐口、门洞上沿这些面朝下的四边形，
  方向光 `max(0, dot(N, L))` 直接夹成 0；HemisphereLight 给它们的也不是天空色而是地面色。
  先试了一盏自下而上的补光，实测同机位 8s 采样 62.1 → 165.2 fps 的代价换 p95 0.06497 → 0.08002，撤掉。
  最终走「把反弹烘进表面」：墙 / 天花 / 横梁各配 `emissive + emissiveMap`（同一张程序化纹理，暖白 `0xffe9c9`，
  强度 0.11 / 0.22 / 0.16），零逐片元成本；HemisphereLight 地面色 `0x10131a → 0x3c4352`、强度 `0.36 → 0.52`，
  天花单独出材质（`#6b5638 / #7c6a4d`）。走廊顶带 p95 0.03496 → 0.04202。
- **只抬反照率没用**：墙基色 `#2f2620 → #3d3026`（1.7×）在 ACES + sRGB 的 toe 段只剩几个百分点，
  而且整帧从 0.072 冲到 0.235 会把书脊反差顶穿。判据用「同一扇区间的 emissive 强度扫一遍看走廊顶带涨多少」，
  不用整帧均值——整帧会被地面稀释。
- **书脊题签**：图集每格加暗色题签底板，字色 `#f7e9c9 → #f7f2e4`，并按 `measureText` 实宽自适应截断（原来按字数硬截 12）。
  反差口径是字色与题签底的比值，门槛线 4.5，实测有书的五区 min 15.21（ai）、p50 15.68–16.95。

## 十、图示渲染（Mermaid，批 3.5 落地）

库里 **855 章含围栏 / 882 个围栏 / 出自 77 本书**〔X〕，占比 73%，所以图不是边角功能。

| 图型 | 围栏数 | 取证书目 |
|---|---|---|
| `flowchart` | 818 | `MATH--bronstein-handbook` ch01 |
| `graph` | 55 | `additive-combinatorics-enlighten` |

| `mindmap` | 2 | `algorithm-enlighten--grokking-algorithms` |
| `xychart-beta` | 1 | `algorithm-enlighten--hello-algo` |

渲染时机是**可见才渲染**，三步走（实现 `src/diagram.ts`，接线 `src/render.ts` 的 mermaid 支）：

1. markdown-it 遇到 ```` ```mermaid ```` 出占位容器：`data-diagram="pending"` + 标题条 +
   `<details class="diagram-src">` 把源码原样留着（源码永不丢，失败即回退给它）。
2. `hydrateDiagrams(root)` 用 `IntersectionObserver`（`rootMargin 160px`、`threshold 0.01`）登记成

3. 失败（语法错 / 不支持类型 / 分包取不到）→ `data-diagram="error"`，容器里给源码 `<pre>` +

约束与代价：

- `securityLevel:'strict'` + `htmlLabels:false` + `theme:'dark'`，产出 SVG 里的 `style` 保留、
  `script` / `on*` / 远程 URL 属性剔掉；实测 5 类图产出 SVG 的远程引用 **0 处**，
  分包合计 57 片 / 5,106KB 全部同源，大厅与分区阶段零 mermaid 请求。
- mermaid 是 `import('mermaid')` 动态分包：主 entry `index-*.js` 418KB 里一个实现字节都没有，
  首屏静态闭包只有 1 片。代价是首次点开围栏要多取一批分包（`mermaid.core` 656KB / gzip 165KB，
  再加所用图型的子包与共享 chunk），所以占位条写明「滚动到此处自动出图」。
- 阅读层收起（`forgetDiagrams`）会把 `watching` 的围栏从观察器摘掉，离开阅读页不会触发加载。

## 十二、渲染层（批 7 落地）

批 2–6 的画面是「颜色填充」：11 处 `MeshBasicMaterial`、零光源、无阴影、无后期。批 7 把它换成有光照的空间，
硬约束是**零外部资产**——不落地任何 `.hdr/.glb/.gltf/.ktx2/图片贴图`，环境光也必须程序化生成。

### 12.1 管线

`WebGLRenderer`（ACESFilmic，exposure 1.0，DPR ≤2）→ `EffectComposer`：`RenderPass → UnrealBloomPass → OutputPass`。
composer 延迟到真正进 3D 视图才建，2D 降级路径不 `import three`（判据：390 视口仍零 three 请求）。

| 件 | 参数 | 为什么 |
|---|---|---|
| HemisphereLight | `0x9fb4de / 0x141a24`，0.42 | 天空-地面双向环境项，比纯 AmbientLight 有层次 |
| DirectionalLight（主光） | `0xfff1dc`，1.5，`castShadow`，mapSize 2048，bias −0.0009，normalBias 0.35 | 唯一的投影灯；俯角 ~38°（`half*0.8`）才拖得出影子，60° 时影子压在柱后看不见 |
| PointLight × 6（大厅逐区） | 学科色，intensity 900，distance 240，decay 2，y=46 | 区的归属靠色光而不是色块；带距离衰减，不会互相糊成一片 |
| PointLight × 2（房间内） | top 学科色 700（distance = span×2.4）+ rim 冷白 392 @ y=18 | rim 挂高是为了不在地面留热点（y=7 时地面有一块过曝） |
| `scene.environment` | `PMREMGenerator.fromEquirectangular` 吃 512×256 canvas 渐变，用完即弃源贴图 | envMapIntensity 0.3–0.5，给金属感与高光走向；零外部文件 |
| UnrealBloomPass | strength 0.55 / radius 0.55 / threshold 0.55，内部分辨率 0.65× | 首值 0.9/0.4/0.5 会把地面暗角糊平，0.35 档又看不出光晕 |
| 雾 | `Fog(BG, 520, 1250)` | 保留，只从 480/1180 微挪一档 |

**阴影只烘一次**：场景静态、只有相机动，所以 `shadowMap.autoUpdate=false`，位姿变化时置 `needsUpdate=true`，省 ~11% 帧时。
**Bloom 内部分辨率 0.65×**：`composer.setSize()` 之后再 `pass.setSize(w·pr·0.65, h·pr·0.65)`（composer 不会替它重算），再省 ~11%。
两者合计把大厅从 ~53fps 抬回 66fps（headless 采样）。

### 12.2 几何

- 立柱 6 种形态，一区一种：数学 `cylinder`、AI `hexPrism`、化学 `coneTower`、计算机 `boxPillar`、通识 `stackedDrum`、工具 `ringColumn`（空房间未建）。
  Lathe/Cylinder/Box 全部代码生成，无外部模型。取证签名 `geometry.type:shape:vertexCount`——单看 type 分不开数学与 AI（都是 CylinderGeometry）。
- 立柱高度 = 章数映射：`base = 3.4 + 7.8·√min(1, 章数/24)`，同书内再乘 0.86–1.0 错落系数，夹在 `[3.4, 11.2]`。√ 让 8 章的书也读得出高度。
- 立柱粗细靠实例缩放 `COLUMN_GIRTH = 2.2`（几何单位半径 0.6–1.0 对展台半径 10 就是根针）。
- 底座 3 种形态（`disc/step/ring`）与立柱同族，一房一种。
- 概念光点：一张 64² canvas 径向渐变共用贴图 + `PlaneGeometry` 面片实例，Additive、`depthWrite:false`；
  半径随题量 `1.5 + 1.15·√min(1, 题量/100)`，颜色 = 学科色向 `#f4f7ff` 插值 0.3，绕柱 4.3 环三层错落。
  总量 math 398 / ai 462，全区 ≤600——**不做粒子海**。
  朝向每帧在 CPU 侧按相机四元数重写实例矩阵：`InstancedMesh.raycast` 读的就是实例矩阵，塞进顶点着色器会让光点点不中。
- 地面：1024² canvas 程序化贴图（40 格细线 + 每 4 格粗线 + 径向暗角），替代原 `GridHelper` 线框。

## 十四、批 10：构图反算与大厅补光

批 9 的三条判据量的是「元素在不在画里」「反差数值够不够」，不是「画面被主体占了多少」「局部读不读得出来」。
批 10 把口径换成占用率与局部明度差，三处改动对应三条新门槛（编号见 `tools/selfcheck_probe.mjs` 批 10 A/B/C）。

### 14.1 竖屏构图反算公式

竖屏不再靠「退机位把东西装全」凑画面（批 9 退到外壳外，正文区只占画面 1/3）。三个自由度一起解：

1. **垂直视野**：`fov = 56° → 76°`（`fovForAspect`，aspect ≤0.55 取满）。
2. **水平挤压（变形宽银幕思路）**：透视矩阵第一项除以 `Kx = 1 + 0.55·ramp`，
   竖屏水平视野乘 1.55，不动垂直视野、不动分辨率；射线拾取和 `project()` 用同一个矩阵的逆，
   点击与投影两套坐标仍然一致（`setFov()` 里矩阵与其逆一同重算）。
3. **机位**：先按垂直需求解距离 `need = span / (tan(fov/2) · Kx)`，
   再与俯视需求 `tiltLen = 92 → 260` 和 `pitch = 38° → 64°` 插值取大者，并夹在 `maxDistance − 20` 内。

```
ramp  = clamp((1 − aspect) / (1 − 0.55), 0, 1)
fov   = 56 + 20·ramp
Kx    = 1 + 0.55·ramp
span  = 142 → 260            // 世界单位：八角壳 + 六走廊 + 六门签的跨度
need  = span / (tan(fov/2) · Kx)
dist  = min(maxDistance − 20, max(tiltLen, need))
```

`hallPose()` 只返回位置，俯仰由 `HALL_PITCH` 与机位方向合成。桌面 ramp = 0，公式退化为批 9 前的基线，
三个数一个不变。阅览室同公式，`Kx = 1 + 0.55·ramp`，机位沿 `side·0.5 − 1.5` 前进。

实测（390×844、dsf 2）：大厅主体（88 个结构点投影包络）竖向 **66.2%**、横向 **83.4%**、六门全在画内；
底部 UI（小地图 + 房间栏 + hud）合计 **12.6%**、与主体重叠 **3.4%**；阅览室主体竖向 **92.9%**、后墙/侧墙各 **2/4** 点入画。
门槛线：竖向 ≥50% / ≥55%、横向 ≥75%、UI ≤22%、重叠 ≤10%。

### 14.2 大厅补光方案

三个病灶都是「局部没有明度差」，不是「整屏不够亮」：

- **藻井梁与井板分不开**：`buildHall` 补一圈 8 扇 × 4 面的藻井环（内径 38、外径 43.6、顶 21.15 / 底 20.75），
  顶面朝下时法线朝天只能吃到半球光的地面色；梁改用深木色 + `emissive 0x1c130b @ 0.7`，且从环面凸出 0.6。
  实测梁/板差桌面 **26.4/255**（门槛 ≥8）。
- **门洞内外分不开**：门外走廊地面与门内八角厅地面原来同一明度。地面材质 `color` 乘子 1.9
  （校准过程：先试整块提亮墙、再试只提 hemisphere，最后发现相机俯冲时地面占画面一半、整帧 p5 全靠它）；

- 大厅总览图（地面纹理区 r=0/12/22 九点均值）**0.379 ≥0.08**。

补光的几何代价：藻井环 +32 面 / +1 draw；梁材质多一个 emissive 参数（常量级）；地面乘子只是 uniform。
桌面大厅 10s 采样 fps **61.1 ≥45**（批 9 同法 93.3，掉的原因是新藻井环 + 地面提亮后 bloom 高光簇变大，
仍在一倍余量内，不为此回退补光）。

## 十五、第一人称漫游（批 11）

轨道视角回答「这个空间有多大、东西在哪」，回答不了「走进去是什么感觉」。批 11 加的是**第二条相机路径**，
不是替换：轨道仍是默认，所有批 2–10 的断言在轨道口径下原样绿。

### 15.1 模式与进出

- 入口两个：`F` 键（`scene3d.onKeyDown`，第一句就是 `if (this.hooks.inputBusy()) return`——阅读面板里的搜索框、
  textarea 聚焦时按键让给用户）与 HUD 的「走进 / 退出」按钮（`#btn-walk`，同时翻 `aria-pressed`，触屏可用）。
- 世界尺度沿用第二节的 `1 单位 ≈ 25 cm`，所以 `WALK` 里每个数都能换算回日常尺寸，不是手感魔法数：
  眼高 **1.65**（人眼高；房间 side 20 / height 15、书架五层总高 ≈11.6，站 1.65 正好平视最下一排书脊）、
  碰撞柱顶 **1.85**（站立身高，只用于竖直通带判定）、步速 **3.2 单位/秒**（横穿一间 20 宽约 6 秒）、
  Shift 疾走 **×1.8**、碰撞半径 **0.45**（≈ 肩宽一半）。**没有跳跃**：竖直方向恒锁在眼高平面上。
- 落位：大厅 → 厅心 `(0, 1.65, 0)` 面朝第一栋楼；区内 → 遍历 `plan.rows`，取**离当前相机最近那一排的正面过道**
  （沿 `row.normal` 外推 `SHELF_DEPTH/2 + 1.15`），朝向顺过道纵深。落位后跑一遍 `settle()`，被盒子吃了就推到面上。
- 退出必须**逐分量复原进入前的轨道位姿**：`orbitReturn` 存 `{camera.position, controls.target}` 六个数，
  切换瞬间冻结 `currentPose()` 的读数（否则漫游自己会把「当前位姿」改写掉）。实测最大差 **0.000 ≤0.05**、
  轨道距离 **351.45 → 351.45**。

### 15.2 碰撞体：绕 Y 的 OBB + 滑动 + 入面判定

阅览室绕 Y 转了 `π/2 − angle`（踩坑 31），六区的墙与书架在世界空间里全是斜的——**AABB 算不了斜墙**：
门洞会被盒角糊住，贴墙走会撞在假墙角上。所以 `src/walk.ts` 的盒子只绕 Y 转，一次旋转把点换进盒子本地系做
「本房间坐标系里的 AABB」，解完再换回来。

- 坐标约定（错了整面墙会横过来，见踩坑 72）：**长轴是本地 z**，`本地 z → 世界 (sin yaw, cos yaw)`、
  `本地 x → (cos yaw, −sin yaw)`；逆变换 `lx = dx·c − dz·s`、`lz = dx·s + dz·c`。于是走廊墙取 `yaw = π/2 − a`、
  八角厅边墙取 `yaw = −a`、房内墙取 `yaw = room.rotation.y`。
- 清单：大厅 **32** 个盒子（`hallWall 2 / hallDoorJamb 12 / corridorWall 12 / facade 6`），
  单间阅览室 **13** 个（`roomWall 5 / doorJamb 2 / shelf 3 / corridorWall 2 / corridorEnd 1`）。
  尺寸全部**复用** `buildRoomShell` / `buildShelves` 那批数（`side / WALL_T / SHELF_DEPTH / row.length / boardY`），
  不另立一套，否则「看得见穿模、算不出碰撞」。进区漫游时大厅是隐藏的，走廊那头必须封口（`corridorEnd`）。
- **不设顶**：外墙、走廊墙、体量外壳的 `y1 = 1e6`。给有限高度就等于给将来加的跳跃留一条绕墙通道。
  书架反过来要真顶（`末层 boardY + pitch + 1.8`），因为它是能贴着走的实体。
- 滑动解算：圆柱对**膨胀盒**（各轴 +r）取最小穿透轴推出去，另一个分量原样保留——贴墙走自然顺墙滑。
  走两趟（斜房转角一趟会留 ~0.1 残穿）。
- **入面判定**（本批真正的坑，踩坑 73）：推向哪一面不能按「人现在在中心哪一侧」算。0.6 厚的墙斜着撞上去时，
  当前侧判据会把人翻到**墙外侧**（实测厅角 190° 方向被抛到 63 单位开外，人从八角厅里漏出去）。
  改成按 `prev`（本帧起点）从哪一面进盒定轴向与符号；`prev` 两轴都在盒外时退回最小穿透轴。
- **搭接**：正好首尾相接的膨胀盒在转角留楔形缺口，沿径向走会被推出到墙外（实测 23° 方向翻到 128 单位）。
  段与段在顶点处搭 **1.2**、房内四墙在转角搭 **0.6**。修完的判据是**扫满 72 个方位**，不是抽四个方向（踩坑 72 教训）。

### 15.3 走通：门洞与六条走廊

门是 `ROOM_DOOR = 7.2 × 9.2`，正门那面墙按门洞宽拆成两段（`dw = min(w, side−2)/2`），两侧各留一截 `doorJamb`
到 `min(9.2, height−1.2)` 高。门楣那段不算碰撞体：人在 1.65 眼高上不会撞楣，算进去等于把门封一半。

实测（`walkMarch` 逐步推进，记第一下阻挡的距离与类型）：

| 六条走廊（厅心 → 各区门面） | 净推进 **131.04–136.68**，第一下阻挡全部来自 `facade`，终点 ±136.55 |
| 八角厅四个实心方位 | **43.08 / 43.08 / 46.44 / 46.44** 被壳拦停，`travelled ≤46.46`，无人翻出壳外 |

### 15.4 准星与拾取

- 转头：拖拽（或右键）改 `yaw / pitch`，`yaw` 不设限、`pitch` 夹 **−70°…+70°**。取 70° 而不是 90° 是为了
  从根上不可能出现万向锁翻转。灵敏度 `lookPerPx = 0.0052`（转 90° 需拖 302px，一屏宽正好半圈）。
  实测横向拖 224px → **Δyaw −66.74°**，纵向顶到底读数 **70 / 70**。**不强制 PointerLock**——那会在页面外冒失焦。
- 漫游态滚轮不缩放：`controls.enabled = false`，缩放与旋转都交还给第一人称自己。
- 准星是画布正中的细十字（34×34，四刻度 + 中心点），纯 CSS、无 HTML 浮标；退出即 `hidden`。
- **拾取只有一条实现**：`ndc = (0, 0)` 走批 8 的 `faceIndex → (book, chapter)` 三角形角色表，
  与俯瞰态点击用的是同一张映射（`scene3d.spinePick`），**没有第二套射线逻辑**。命中书脊 → 准星加 `on-target`
  + HUD 底部报「书面 · 第 N 章 · 点击读正文」。实测站位 `(−142.57, −6.95)` 命中 `ch03`，点一下开的正是
  `additive-combinatorics-enlighten.json` 的 `ch03`（`mode: chapter`）。判据要求命中的是**章**不是书：
  书脊铜牌（书）与书脊本体（章）在 faceIndex 表里本来就分属两档，漫游态不做特殊分支。

### 15.5 触屏分区：左摇杆 / 右转头 / 轻点

分界线 `x = window.innerWidth / 2`（390 视口即 **195px**）**只在这份文档里存在**，页面上不画线——画出来就成了
HTML 浮标，违反第八节。判定：

1. `touchstart` 落在 `clientX < innerWidth/2` → 归摇杆；否则归转头。
2. 摇杆**在指头落点处出现**（96px 底盘 + 40px 把手，半透明，非跟随不可见），行程 48px、死区 `0.18`；
   松指归中并 `hidden`。
3. 轻点判据**先看位移、再看时长**：`moved < 8px`（触屏；鼠标 6px）过了之后，再要求按压 `< 700ms`。
   顺序反了会把「按住不动看东西」误判成点击。实测 900ms 长按 → `{ moved: 0, slop: 8, action: 'drag' }` 且正文未开。
4. 拾取走准星（ndc 0,0），不走触点坐标——所以点哪儿都开同一章，与「你在看什么」一致。

实测 390×844：`scrollWidth 390`；准星盒 (178, 396, 34×34) → 横向中心 **195 = 390/2**（门槛 ±3px）；
「走进」按钮 54×38（触屏目标线 ≥44×32）；学科条顶边 **771**，摇杆实时盒 **(42, 572, 96×96)** → 底边 668，与学科条相隔 **103px** 不相压。左半屏拖 (90,620) → (90,520) 净位移 **0.7**、`vec {active:true, y:1}`；
右半屏拖 (300,420) → **Δyaw 46.48°** 且位移轨迹**零采样**（人不挪步、摇杆不出现）；轻点 (195,420) 开章。

### 15.6 漫游态材质与近景贴图账

俯瞰那张「平面方案图」地面（`spacekit` 画的网格 + 分区标注）在 1.65 眼高上是**横条纹**：整张图摊在 r≈180 的
半径上，只有 **10.8 texel/单位**，再加批 10 的 emissive 0.9 直接糊成一片亮板（踩坑 74）。所以漫游态换一套：

- `applyWalkSurfaces(true)` 只换地面与大厅材质，退出原样换回（`walkMatPairs` 记账，幂等）。
- 地面换程序化石板：`repeat 14`，实测 **37.6 texel/单位**；`roomFloor` 61.0、`wall` 34.1、`spines` 45.6（p90 162.7）。
- 墙/天花/藻井/走廊壳/体量**克隆**一份加 `emissive 0xffe9c9`（强度 0.11–0.17）。`Texture.clone()` 共享 `source`，
  只多一份 UV 变换，不额外上传显存。
- 全部 `generateMipmaps = true`、`anisotropy = 8`（设备上限 16），门槛线 ≥4。
- 不新增任何外部贴图文件：石板、木饰、皮革全走 `spacekit` canvas。

漫游态桌面 10s 均值 **57.1 ≥45**（大厅 32 个碰撞盒的解算是每帧常数级，成本在贴图上不在物理上）。

## 十六、中央索引台与展柜（批 12）

### 16.1 为什么不改尺度

批 11 收口时大厅漫游是塌的：`walk-hall.png` 站在厅心，眼前一整面暗褐内壁、地面露一条、六面门洞读不出。
