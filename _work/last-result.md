## 收尾查出的问题（都是实测逼出来的，不是门槛放宽）

1. **台面被 bloom 洗成白片**（真画质 bug，门槛当时全绿）：`emissiveMap` 与 `map` 同一张图 + 近台 `emissiveIntensity 1.25`
   + 一盏 32 强度点光贴着台面上方 1.25 单位（`decay 2` 下中心辐照 ≈20）+ 全局 bloom `threshold 0.6 / radius 0.5`
   → 1024² 方位图的区名读不出。修法：**抬灯**（y 2.75、`distance 10→12`）而不是降灯，自发光收到 0.62/0.90、灯带 0.95/1.30、点光 14/18。
   判据用 `brightRatio`（>0.75 的占比）不用平均亮度：mean 0.511→0.367、亮部占比 26.3%→16.0%（已验证 82）。
2. **台面文字「字头朝外」是倒字**：`atlas.ts` 里 `g.rotate(s.am + Math.PI/2)` 的注释理由（朝外省力）反了——
   人站台边看台心时屏幕上方正是台心方向，改成 `s.am − Math.PI/2`（已验证 83）。隔着台面读对侧仍倒，是罗盘桌固有性质，不做双面绘制。
3. **`camera.matrixWorld` 陈旧导致准星读「转身之前」的目标**（真产品 bug，门槛两轮红逼出来的）：
   `Raycaster.setFromCamera` 取的是 `camera.matrixWorld`，而它只在 `render()` 里更新；`walkSnapTo` 瞬移后立刻算准星，
   拿到的是上一帧朝向 → 近台 HUD 读到的是门面提示。修在 `refreshAim()` 开头补 `this.camera.updateMatrixWorld()`（已验证 84）。
   探针侧同时把「默认提示」的读数显式归零俯仰（台面在眼高以下，俯仰不归零就继承上一项测试的命中口径）——这是收紧不是放宽。
4. **`Raycaster.intersectObject` 不看 `visible`**：扇区高亮块留在拾取目标里会把台面挡住，得进 skip 名单（已验证 81）。
   这也是铁律里「高亮块必须留在 skip 名单」那条的出处。
5. **环视目标表按角色名硬写，两处各一份早晚会漂**：首跑 `hallSightScan` 把 `sectorHl` 当内容算，读数里出现空 `role`
   与短得离谱的 `wallDist` → 目标表改成按「画面上真存在的东西」显式构造 content/skip 两个集合。
6. **门洞扫描第一版打到对侧墙**：射线穿过门洞继续撞到对面 `hallWall`，质心方位偏出十几度 → 只打 `hallWall` 外壳 + `openMin 60`。
7. **扇区「六等分」的直觉是错的**：门洞本身不等距（45/90/135/180/270/315），六等分必然大于 ±3°；
   改角平分线后宽度天然不等（67.5/45/45/67.5/67.5/67.5），断言口径随之改成逐区 `a0/a1 ±2°` + `sumDeg 360 / maxSeam 0`。
8. **展柜射灯断言写死 2.4 假绿风险**：材质初值与近台值是两档（2.0/2.2），判据改区间 2–3.5。
9. 编译期两处：`architecture.ts` 里一个未使用变量触发 **TS6133**（`tsc --noEmit` 挡住）；
   `tools/README.md` 的自检条目还停在「126 项 / shots-batch11」，一并改到 164 项（探针 145 + gate 19）并补批 12 诊断接口清单。
10. **文档里凭印象写了不存在的符号**：`src/hub.ts` / `buildIndexDesk` / `routeToDoor` / `caseSpineAim(i, j)` 都是臆造，
    逐个核对源码后改成 `architecture.buildAtrium` / `atlas.indexDeskTexture` / `config.ATRIUM` / `aimDeskRay` /
    `aimDeskSector(i)` / `aimCaseBody(i)` / `aimCaseSpine(k)`（k 是全圈 15 根脊的下标）。教训：**文档里的符号名必须 grep 得到**。
